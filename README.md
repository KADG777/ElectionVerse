# ElectionVerse：青岚镇市长选举

Godot **4.7.2**、GDScript、原生 Control/HTTPRequest 的单人 2D 多 Agent 叙事原型。玩家与陈远争取七位居民的选票，三轮事件分别是工厂扩建、公共预算与暴雨损桥。默认 **Mock 离线模式**，无需 Key 即可完整游玩。

GitHub 仓库：[KADG777/ElectionVerse](https://github.com/KADG777/ElectionVerse)。凭据忽略规则与提交前检查见 [SECURITY.md](SECURITY.md)。运行日志、存档、缓存与验证截图保留在本地，不纳入 Git；可用测试入口重新生成验证结果。

## 打开与游玩

双击 `启动游戏.cmd`；或用 Godot 打开 `project.godot`，按 F6/F5 运行。当前开发位置为 `D:/CS Games/ElectionVerse`，与之前两个游戏独立。启动脚本优先使用 `engine/Godot.exe`，否则使用本机 `D:/godot/Godot_v4.7.2-stable_win64.exe`。源码包不包含引擎；换电脑需安装 Godot 或加入便携引擎。

1. 新选举 → 设置姓名、固定种子与运行模式 → 开始。
2. 阅读每轮事件，在文本框自由输入方案（1–1200 字）。支持/反对/折中只负责填入可编辑示例。
3. 提交后陈远发言，七居民逐个独立评价；此时不能重复提交或跳轮。
4. 阅读双方评价、信任与变化理由。点居民卡可查看固定人格和该居民自己的记忆；历史面板可按轮查询事件。
5. 三轮后公开计票，逐人显示选票、历史依据和最终评分；结构化导出包含各项得分。可导出故事记录与 Markdown 摘要。

第二轮总预算 **100 万元**。建议明确写 `教育40万、医疗30万、养老20万、基建10万`；不投入的部门写 `0万`。支持常用阿拉伯/中文金额，`元`会换算成万元。没有金额、缺部门、负数或超支方案会被标记，不能无代价满足全部诉求。双方预算是竞争方案，各自接受同一个 100 万元上限，不会合并从世界资金里扣两次。

## Qwen 模式

设置页可填写密码样式 API Key、自定义 Base URL、模型名称，并测试连接或保存本次会话配置。默认地址 `https://dashscope.aliyuncs.com/compatible-mode/v1`、模型 `qwen-plus`。地域/业务空间须与账号 Key 匹配；地址始终可编辑。配置细节和官方文档见 [Qwen 接入说明](docs/Qwen接入说明.md)。

Key **只在当前进程内存中**；没有 Key 时 Agent 使用 Mock，不写入存档、事件或项目配置。连接测试不会假装离线成功。全游戏正常为每轮 8 次请求、共 24 次，另有用户主动测试/失败重试；不进行无限自主对话。

每次真实请求默认超时 25 秒。JSON/Schema 错误仅纠正一次，仍失败则只把该 Agent 降级到 Mock，并记入事件日志。网络、鉴权、额度等失败进入明确恢复页，可重试当前阶段，或让 Mock 接管剩余 Agent；已成功的发言和评价不会重复执行。HTTP 等待期间界面持续响应。

统计展示调用数、耗时、失败/纠正次数及服务提供的 Token 用量。缺失用量明确标为未提供；已知部分的累计不能当完整总量。本轮没有提供真实 Qwen 凭据，未声称真实账号调用已经验收；已执行原生 HTTP 回环、超时和故障恢复检查。

## 七名独立居民与规则

林老师关注教育与长期公共服务；周师傅关注就业和劳动保障；许医生关注健康、环境与证据；苏晴关注青年和创新；王奶奶关注养老、安全和生活成本；赵老板关注商业、基础设施与信誉；李记者关注透明、程序和承诺一致性。固定设定在 `data/residents.json`，不随某轮评价重写。

每人对双方分别维护：0–100 的综合评价、0–100 的信任、九维政策评价、承诺一致性、关系和独立记忆。双方评价不要求相加等于 100。Qwen 只输出该居民对双方的文字反应、九维 -1..1 主观判断、-1..1 信任信号和记忆摘要；不能直接设置评价总值、选票或执行任意状态指令。

规则代码在 `scripts/core/RuleEngine.gd`，双方完全相同：

- 政策影响：居民九维权重 × 本轮议题重要度 × 主观评价，除以权重总和。
- 信任变化：信任信号 ×3，加具体措施项（+1 / 空泛 -0.8），减矛盾承诺每项1.4；无效方案再减5，单次限制 ±6。
- 综合评价变化：政策影响 ×10 + 信任变化 ×0.45 − 矛盾每项0.8，单次限制 ±14，总值限制0–100。
- 无效预算将政策影响限制到不高于 -0.4，政策向量不能因此获得正收益。政策向量按旧值0.65 + 本轮0.35更新，维度限制 -1..1。
- 公开/核验承诺的明确反转会形成一致性扣分，不把不同事件的正常立场差异机械当成自相矛盾。

最终计票代码 `VotingSystem.gd`：综合评价×0.45 + 信任×0.30 + 个体加权政策×12 + 一致性×2 + 重要记忆（总上限±1.5）+ 关系×0.08 + 固定种子个体犹豫（±0.6）。七人各一票，无总体平票。输出每项分解和该居民实际历史依据。计票是纯函数，**同一状态与种子产生相同结果**；真实模型每次生成的文字/评价可能不同，固定种子并不保证远程模型生成完全相同。Mock 全流程不依赖远程随机结果。

本地自然语言解析使用明确关键词、否定词、金额和单位，不宣称通用语义理解。Qwen 居民还会读取完整演讲，但本地预算与白名单限制始终优先。每轮产生新的世界公开档案、核算后的竞争方案与事件进度，未声称候选人尚未当选就已执行所有建设。

## 记忆、状态机与存档

`EventLog` 使用统一事件 ID、轮次、类型、行为者、内容、可见身份、效果和逻辑时间。居民只读取 all 或本人被授权的事件；自己的主观判断保留在本人记忆，其他 Agent 不会读取这份私有记录。发送模型前仅选最近12条获准事件和最多6条重要记忆摘要。玩家以全局观察者身份可在管理面板审阅角色状态，审阅不等于所有 NPC 已互相得知。

菜单与配置由界面处理；游戏状态按 `ROUND_INTRO → WAITING_PLAYER_ACTION → AI_OPPONENT_TURN → RESIDENT_EVALUATION → ROUND_RESULT → NEXT_ROUND` 推进，第三轮转 `FINAL_VOTE → GAME_OVER`。失败使用额外 `RECOVERY` 阶段。状态管理器拒绝非法提交/跳轮，评价按轮次、居民、候选人组成唯一结算标识。

每个稳定轮次/恢复点自动保存，也有手动存读档。存档写入 `user://election_save.json`，替换前保留 `.bak`；包含轮次、所有角色、世界状态、日志、结算标识、随机种子和恢复缓存。损坏结构、越界数值、人格覆盖、错误事件序号/重复 ID 会被拒绝，读档不重放已结算事件。API 配置不包含在存档中。

故事导出为 `user://story_events.json` 和 `user://election_summary.md`，统一 Schema 可供未来 StoryVerse 工作流读取；不启动小说生成服务。实际导出位置会在游戏中显示。Windows 通常位于 `%APPDATA%/Godot/app_userdata/` 对应游戏目录。
